# 跨端核心规格

两端（Android / PC）的**判断逻辑必须与本文逐条一致**。事实来源是 `docs/PROTOCOL.md`；
本文把它写成可照抄的规则与测试向量。任何一端偏离，都要先改这里再改代码。

## 1. 落点

```
entry = JXFW（默认）   → 前缀已记：<前缀>/student/sso/login
                        前缀未记：https://webvpn.sues.edu.cn   （先走门户读出前缀）
entry = WEBVPN（次要） → https://webvpn.sues.edu.cn
```

记下的前缀必须**通过形状校验**才允许写入与使用：

```
^https?://[^/]+/https/[0-9a-fA-F]+$
```

- 只认形状，不认具体取值（编码是网关按目标主机+端口算的部署细节）。
- 带子路径、非十六进制、缺协议一律视为无效，**不记**。

## 2. 页面身份

身份一律按**文档内容**判定，**不得只看 URL 形态**——认证页提交前后的地址逐字节相同。

| 判断 | 判据 | 说明 |
| --- | --- | --- |
| 认证页 | URL 含 `/cas/login` | 会话过期时网关会把请求弹到这里 |
| **密码错误** | **认证页** 且文档含 `#msg1`（或 `name="error_fm1"`、`.form-error` 容器），其文本含 `密码错误` / `密码不正确` / `用户名或密码` / `账号或密码` / `用户不存在` / `账号不存在` / `用户名不存在` | 服务端把错误文案放在 `#msg1`；`#msg2`/`error_fm2` 是短信表单的，不要混用 |
| **密码已过期** | 正文含 `密码已过期` | **判据优先级最高**：过期提示的文案本身就写在 `#msg1` / `.form-error` 容器里，先看「有没有提示文本」会把它整个挡住。**只对部分账号弹出**：不弹属正常路径，不得当成异常；反之也不得假设它一定不出现 |
| **换票中转页** | 主机 `webvpn.sues.edu.cn` 且路径以 `/wengine-vpn/failed` 开头 | 换票链的中间落点（正文是「出错啦！该网站无法访问…」），**不代表登录失败**；不判失败、**不据此清前缀**，见 §4 |
| 教务系统 | 正则 `/https/[0-9a-f]+/student/` | 老教务走 `/http/`，不算 |
| 二次登录页 | 是教务系统 **且** URL 含 `/student/login` | 门户卡片 `/student/home` 会 302 到这里 |
| 前缀失效 | 用缓存前缀直打教务系统，却落到既非教务系统、也非认证页、也非中转页，且本次未经过认证页 | 清掉前缀，下次回门户重读 |

> `/student/sso/login` **不含** `/student/login`（中间多了 `sso/`），两条判据不会互相误伤。

**「成功」的判定**：不得只看 URL 是否落在 `webvpn.sues.edu.cn`——中转页也满足它，那只说明「到过」。
权威判据是页面正文含 `个人信息` / `注销` / `资源站点`（`注销` 只对已登录用户渲染）。
`window.__NUXT__.userInfo.username` 实测恒为空串（SPA 的 SSR 初始值），**不可用作判据**。

**落地方式（两端一致，2026-09）**：门户入口（`entry=WEBVPN`）落到任何既非认证页、也非中转页的页面时，
状态机返回 `VerifyArrival` 而不是直接停手；宿主执行 `shared/js/arrival.js`
（返回 `arrival|<命中的标记>` / `arrival|none` / `arrival|err`），**命中才停手**
（`ConfirmArrival`），没命中就**不宣布到达**：不清待判决标志、不落盘凭据、只留一条状态。

教务系统入口（`entry=JXFW`）**不适用**这三个标记——它们是门户的，教务系统首页没有；
那一支的判据是 `/https/<编码>/student/` 这个已经足够具体的地址形状（中转页由主机+路径排除）。
把正文判据套到那一支会让主路径永不落定，所以刻意不套。

**剩余尝试次数**：不要写死句式，找所有 `(\d+)\s*次`，看它前面约 12 个字符内是否出现
`再` / `还` / `剩余` / `剩` / `可再` / `尝试` / `输错` / `错误`。命中即为剩余次数。
实测文案「密码错误。再输错3次，账号将被锁定。」→ 剩余 3 次。文案可能有嵌套标签与 `<br>`，
取文本要用深度感知的解析（`<br>`/`<hr>` 是 void 元素，**不改变嵌套深度**），不要用非贪婪正则。

## 3. 从门户读出前缀

首选同源接口（一次就够，实测 20 KB 左右）：

```
GET /user/portal_groups      （相对当前页；同源、带 cookie）
```

在返回里找 `resource`：`detail` 或 `url` 含 `jxfw.sues.edu.cn`，且 `redirect` 以 `/https/` 开头；
取 `redirect` 的**绝对化结果**再 `substringBefore("/student/")`，校验形状后即为前缀。

异步实现的约定（WebView 里 `fetch` 是异步的）：结果留在页面全局变量上，由**下一发**探测读取。
探测按 600ms 一发、最多 15 发自续重试。

兜底（接口拿不到时）：在 DOM 里找 `<a>`，文字含 `jxfw.sues.edu.cn`；或「`href` 含 `/https/`
且文字含『教务』」。

## 4. 停手规则（状态机）

### 4.0 「一份文档」的定义（宿主必须照此记账）

- **`about:blank`（与空串）不是一份文档**，宿主的导航回调遇到它必须**直接返回**：既不
  `OnDocumentStarted`，也不 `OnDocumentFinished`。新建 WebView 的初始空白页也会走这两个回调；
  把它记成一份文档，就会让紧接着那份**真页面**的 `OnFinished` 被「每份文档只处理一次」的账本吞掉
  （`_handled == _docs`）——表现是**自动登录偶发失效**，而且完全看时序、日志里只有「什么都没发生」。
  这是 2026-09 做宿主层测试（真机真实 WebView）时查出来的。
- **判断「当前是哪一页」一律用状态机判过的那份文档的 URL**（Android 缓存在 `Tab.documentUrl`，
  由导航回调写入），不要读控件的实时属性：`WebView.getUrl()` 在**初始空白页返回 `null`**、
  在合成文档上返回 `about:blank`，而 `samePage("", null)` 为假会让整段认证页观察被**静默丢掉**。
  PC 的 `CoreWebView2.Source` 本身就是「当前文档的 URL」（且不为 null），语义与之一致。
- **「脚本这一跳之间页面换没换」比文档 URL，不比文档序号**：某些装载方式会对同一份文档多来一次
  `onPageStarted`（序号自增而页面并未更换），比序号会把结果误丢（实测：正例偶发失败）。

每一份新文档（不是每一次回调——同一份文档会重复回调）按顺序判：

1. **认证页**：
   - 文档含「密码错误」文本（§2）→ **立刻停止本次自动流程**：不再填写、不再提交、不再拖滑块，
     按 §6 处置凭据，把页面交给用户。**不重试**（服务端累计次数，5 次锁号）。
   - 否则 → 只做辅助：勾 `rememberMe`；正文含「密码已过期」时**点掉「点击跳过」**（按文字找，
     不假设元素类型；找不到就重载当前 URL——那正是该按钮 `onclick` 所做的事），
     **一次运行最多跳一次**，跳完又回到这一页就停手并提示用户；在用户已授权且有已存凭据时
     填写并**提交一次**；装滑块监视器；用户已授权时装凭据监视器。把「已停手」复位，然后返回。
     **认证页不受其它规则约束**（会话过期、被踢下线都会弹回这里）。
   - 辅助的边界：每个文档只填一次；**每次流程替用户提交至多 2 次**（服务端若只回干净表单页
     而不置错误文案，没有上限就会一份接一份地填下去——每一次都在消耗失败次数）；否定发生时
     若归因不是已存凭据（用户手动输错）且用户仍同意保存，要在否定页**重装凭据监视器**——
     用户改对再登的那次提交应被捕获。
2. 已经停手 → 返回（不再导航，但第 1 条仍生效）。
3. **换票中转页**（§2）→ 不判失败、**不清前缀**、不探测门户，等页面自己往下跳；停留超过 15 秒
   仍未到教务系统，才允许**重载一次**（只此一次）。
4. 二次登录页 → 提示用户自行登录（或点另一个入口重试），**不自动填任何东西**。
5. 教务系统 → **停手**。
6. 入口是 WebVPN → **停手**。
7. 属于「前缀失效」（见 §2）→ 清前缀 + 提示。
8. 其余 → 探测门户（§3），读出前缀后打 `<前缀>/student/sso/login`。

「停手」= 不再替用户导航。除了认证页上那**一次**填写与提交（且仅在用户已授权、已存凭据、页面
同时存在 `#username` 与 `#password` 时）之外，**没有任何一处会替用户提交账号密码**；也没有任何
"猜兜底路线"的分支：落点不认识就交回用户。

## 5. 滑块

### 5.1 门禁（什么时候允许拖）

- 文档里**没有** `#password`（这是独立的「滑动登录」文档，本身不含凭据）→ 页面一渲染出
  `.ap-container` 即可接管。
- 文档里**有** `#password` → 必须等用户按下「登 录」且表单**真的提交**（监听 `submit` 事件）
  才接管；禁止用轮询密码长度来猜（加密与提交发生在同一次点击里）。
- **接管只有一个判据：`armed`**（页面脚本上报）。它已经把两种形态都表达了：
  无密码框的文档一有 `.ap-container` 就 `armed`；有密码框的文档在真实 `submit` 之后 `armed`
  （`expectsSlide` 只用于诊断日志，**不得**参与分支）。2026-09 修正：早先 JS 的上报门禁与宿主的
  分支都额外要求「这份文档没有密码框」，于是「表单与滑块同页」那一形态提交后
  **图片永不上报、宿主两个分支都不命中**：不拖、不提示、不超时、`captchaAttempts` 永不增长。
- 同一张图（以两张图的**完整 data-URL** 为身份）只报一次。
- 每个登录文档最多自动拖 **3** 次；接管后 **20 秒**等不到滑块就放弃并提示手动完成；
  **拖满 3 次仍失败要明确提示一次**「请手动拖动」——换新图后静默不再处理会让用户以为卡死。
- 页面监视器（滑块/凭据）在应用退到后台时停、**回前台重装**（脚本自带幂等护栏，重复注入无害），
  否则后台回来后自动滑块会静默失效。
- `armed=false` 的上报**只撤超时定时器，不清状态行**：监视器装上后第一次上报必然是
  `armed=false`（页面有密码框、还没提交），把它当成「收起提示」会把该留下的提示在 400ms 内
  擦掉。滑块监视器不拥有状态行，提示由后续的判决（成功/失败/到期）替换。

### 5.2 定位（算法与参数）

```
模板  = 整幅滑块图（裁剪会整体偏 +19 px，禁止裁剪）
掩码  = 模板像素满足 299R + 587G + 114B > 12000
评分  = 掩码内**三通道展平、不减均值**的归一化互相关（等价 cv2 TM_CCORR_NORMED）
搜索  = 只在 1.0 档（背景图上按列滑窗，x 从 0 到 bgW - slW）
输出  = 评分最高的列号 x
放弃  = 尺寸不合法 / 掩码像素 < 64 / 模板能量为 0（掩码内三通道全 0）
```

服务端容差 ±2px；上述配置在 80 例真值语料上「单次提交 |x−真值|≤2」为 **77/80**。

> **2026-09 修正**：早先这里写的是「Pearson 之和」（即**逐通道减均值**那一版，参考实现里叫
> `ccoeff`）。同一批语料上那版只有 **64/80**，与本节声称的 77/80 **自相矛盾**——而两端实现
> 恰好照着错的那半句写的，缺的正是这 13 个百分点。真值语料基准见
> `D:\webvpn\lab\bench_campusentry_csharp`（PC 端换度量后与参考实现逐例一致 80/80）。
>
> 两者不可混用：减均值会把服务端那层「掺白 + 去饱和」的平移当噪声压掉，连真值处的优势一起压没。
> **合成图单测下两种度量给出同一个答案**，所以改这个度量必须用真值语料回归，不能只看单测。

解码要求：位图**不要预乘 alpha**（Android 用 `BitmapFactory.Options.inPremultiplied = false`，
等价于 PIL 的 RGBA→RGB），否则滑块 PNG 半透明边缘的 RGB 会被改掉，候选表与参考实现不一致。

### 5.3 拖动（换算与反解）

页面提交的值是 `parseInt(光标 / 滑轨长度 × 值域)`。**这是两个不同的量，混起来就系统性偏移**：

```
值域     = 两图自然宽之差（440 − 80 = 360）        # 页面里叫 cutScope / data.scope
滑轨长度 = 容器渲染宽 − 手柄内容宽                  # zoom=0.75 时 330 − 45 = 285
         ≡ 容器渲染宽 × (440 − 60) ÷ 440            # 与上式代数等价
反解     = round(x / 值域 × 滑轨长度)，再在附近枚举 ±4 个整数，取「提交值最贴近 x」的那个
位移     = 光标 − 手柄当前光标位置                  # 位移是相对量：pos = (clientX − start.x) + start.cursor
```

**手柄内容宽不能用 `offsetWidth`**：它含 1px+1px 边框（47 而不是 45），滑轨会被算成 283 而不是 285，
提交值整体偏 2px，正好吃掉服务端的 ±2 容差。

**滑轨长度不是 `值域 × zoom`**（那是 270）。值域是提交值的范围，滑轨是手柄能走的显示层像素。
把两者混起来，提交值会变成 `0.947x`——一直偏短且 x 越大偏得越多（x=200 差 11px，x=360 差 19px），
远超 ±2 容差，表现为「每次都偏移」。这是本工作区犯过的错，见 `docs/APP-UX.md` §10。

事件序列：先勾一次 `#rememberMe` → `mousedown` 派发到拖块（`.ap-bar-ctr`）→ `mousemove`、
`mouseup` 派发到 `document`；`MouseEvent.x` 即 `clientX`。

> **这段算术要放在能被单测覆盖的地方**（各端用各自的语言写），不要只写在注入页面的脚本字面量里。
> 本工作区第一版就是写在 JS 字符串里，于是这个 5% 的偏差在电脑上一条测试都拦不住。

## 6. 凭据（两端一致的硬规则）

跨端只规定**规则**；密钥与存储由各端平台机制实现（Android 用系统密钥库，见 `docs/APP-UX.md` §6.2）。

1. **只在学校的统一身份认证页面上填写**：当前文档主机是 `webvpn.sues.edu.cn`、URL 含 `/cas/login`、
   且文档同时存在 `#username` 与 `#password`。网关改写的第三方页面、教务系统自己的二次登录页，
   **一律不填**。

   > **落地（2026-09）**：主机 + 路径由 `Sues.IsCredentialPage` 一次判定（两端同源，与
   > `IsCasPage` 分开：后者是**页面身份**，只看路径，用于状态机；前者是**允许碰凭据**的门槛）。
   > 宿主在认证页辅助的入口处用它做第一道闸（不是的页面一律不动），并在**凭据捕获处再判一次**
   > ——页面脚本可以主动伪造一次提交，这件事不能只靠页面侧。「文档同时存在两个输入框」由页面脚本判
   > （返回 `noform`，宿主据此作废这次填写）。
   >
   > **判据的输入必须是「状态机判过的那份文档」的 URL**，不是控件的实时属性。
   > Android 把文档 URL 缓存进 `Tab.documentUrl`（由导航回调写入）：`WebView.getUrl()` 在
   > **初始空白页返回 `null`**、在合成文档（`loadDataWithBaseURL`）上返回 `about:blank`，
   > 于是 `samePage("", null)` 这类比较会静默为假——表现是**整段认证页观察被丢掉**
   > （不勾「记住我」、不装监视器、不自动填），而日志里一条错都没有。
   > 这是 2026-09 做宿主层测试时查出来的：Android 侧已改成文档身份（`Tab.documentUrl` +
   > 文档序号）；PC 读 `CoreWebView2.Source`，它就是**当前文档的 URL** 且不会为 null，
   > 所以行为一致、没有这一处脆弱点——但它同样不该改成读别的属性。
2. **每次认证只提交一次**。不自动重试。**每次流程替用户提交至多 2 次**（硬上限，见 §4）。
3. **密码错误 → 删除已存凭据并停用自动登录**。因为错误文案只可能来自服务端对凭据的否定，不可能
   由网络或渲染问题造成；留存错的凭据等于每次启动都自动消耗一次失败次数，直达锁号。
   - **归因用「待判决标志」，不用文档序号**：登录提交是整页导航，否定的回应是**下一份新文档**
     （`docs/PROTOCOL.md` §6），「文档序号相等」永远差一。标志在应用真的按下登录那一刻置位；
     用户自己提交、登录成功、或重开流程时清掉；否定发生时**读走一次即清**（第二次否定不会
     再次归因给应用、不会重复删库）。
   - 只有归因给已存凭据时才删除；用户手动输错时不动凭据，且要在否定页**重装凭据监视器**，
     用户改对再登的那次提交应被捕获（首登承诺才兑现）。
   - 若解析到剩余次数 **≤ 1**，**硬性阻断**任何重试路径，并把剩余次数原样告诉用户。
4. 凭据不得进入日志、剪贴板、Intent 或界面状态保存；界面展示的用户名一律打码。

## 7. 等价测试向量（两端都要有等价用例）

**落点**

| 输入 | 期望 |
| --- | --- |
| `entry=JXFW`，无前缀 | `https://webvpn.sues.edu.cn` |
| `entry=JXFW`，前缀 `P` | `P + "/student/sso/login"` |
| `entry=WEBVPN`，前缀 `P` | `https://webvpn.sues.edu.cn` |

**前缀形状**（`P` = `https://webvpn.sues.edu.cn/https/<32+ 位十六进制>`）

| 输入 | 期望 |
