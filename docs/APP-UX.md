# 「教务直达」页面逻辑与交互规划

> 状态：**§9 的 A、B 两期已实现并验证**（判据修正、凭据库）；C、D、E 未开始。
> 界面部分仍是规划稿——代码里还没有这些界面。
> 视觉 token 见仓库根目录 `DESIGN.md`；协议事实见 `docs/PROTOCOL.md`；跨端核心规则见 `docs/CORE-SPEC.md`。

## 1. 这一版要解决什么

现状：应用能打开教务系统与 WebVPN，能自动拖滑块，但**每次冷启动都要用户手动输一次账号密码**。

目标：**保存账号密码（加密），打开即已登录**。同时把界面重做一遍——重视人机交互、符合直觉、美观简洁。

达标判据（真机验收）：

1. 已保存账号后，从点图标到看见教务系统首页，**用户零操作**，过程不需要停留。
2. 首次使用（未保存账号）**只多一次**输入，且用户清楚知道「这一次输完，以后不用再输」。
3. 任何一步出岔子，用户**一眼知道卡在哪、要不要自己出手**，且能自己收场（重试 / 手动登录 / 清除账号）。

## 2. 三条设计原则

1. **零操作优先，但不偷偷做事。** 能自动的全自动；但每一件替用户做的事，屏幕上都有句话在说。已经替用户输入了凭据这件事，必须在**他按下登录之前**就说清楚，不是事后通知。
2. **随时可打断、可接管。** 自动流程的每一步都能被人的操作接管；失败不重试、不猜兜底路线，把控制权交回去。
3. **诚实。** 包括对安全边界的诚实：加密保护什么、不保护什么，写在界面上和文档里，不写成"军事级加密"这类空话。

## 3. 页面清单（信息架构）

**只有两个页面 + 一个抽屉**。不做多余层级。

| 编号 | 名称 | 形态 | 何时出现 |
|---|---|---|---|
| P1 | 入口页 | 独立页面 | **首次自动出现**；之后随时可从抽屉第一行「入口首页」进入 |
| P2 | 浏览页 | 独立页面（内含 WebView） | 常驻；应用的默认界面 |
| P3 | 账号抽屉 | 底部抽屉（BottomSheet） | 用户点底栏「账号」时 |

**关键决定：已保存账号后不再自动经过 P1，打开应用直接进 P2 并自动登录。** 这是一个"快捷方式"，多一次点击就违背了它的存在意义。但 P1 不会消失——它随时能从账号抽屉进入，只是不再挡在打开应用的路上。


- **底栏三项**：教务系统 / WebVPN / 账号。激活项用交互蓝，其余石板灰。
- **不放「返回」按钮**：返回交给系统返回键/手势（有历史则后退一页，没有则退出应用）。这是 Android 用户已有的直觉；省下的位置给「账号」。
- **状态行只在有事发生时出现**：**浮在页面之上**贴着底边，既不占布局高度、也不改变 WebView 尺寸
  （避免页面重排跳动），2 秒后自动淡出；需要用户出手时**常驻**并可点击。底栏因此只有它自己那一行。
- WebView 内**不做**算法反色，深色模式下学校页面保持原样。
- 页面加载失败 / 证书失败：状态行换成可点的告警条，证书失败**不提供"继续访问"**。

### P3 账号抽屉

```
┌──────────────────────────────────────┐
│  ─────                               │  拖拽把手
│  账号                                 │  16/600
│                                      │
│  入口首页                          ›  │  52px 行，主动进入 P1
│  ────────────────────────────────    │
│  已保存：2021****（张三）              │  52px 行
│  ────────────────────────────────    │
│  自动登录                        [开] │  52px 行，开关
│  ────────────────────────────────    │
│  收起公告弹窗                    [开] │  66px 行，开关
│  站点那个没有关闭按钮的公告弹窗          │
│  ────────────────────────────────    │
│  清除缓存 · 退出登录                    │  66px 行：清掉登录状态，密码不动
│  清掉学校的登录状态，保存的密码不动       │
│  ────────────────────────────────    │
│  清除账号                              │  66px 行，红字（文字按钮，不做红底）
│  删掉保存的密码，登录状态不动            │
│  ────────────────────────────────    │
│  改用其他账号                          │  66px 行：退出登录并删除密码
│  退出登录并删除保存的密码                │
│  ────────────────────────────────    │
│  密码用系统密钥库加密后存放在本机。      │  12/400 secondary，3 行以内
│  应用只在学校的统一身份认证页面上填写，   │
│  从不发送到别处。清除后立即失效。        │
└──────────────────────────────────────┘
```

- 第一行「入口首页」是 P1 的后门：两个入口的大卡片 + 账号开关，随时可看可改。
- **抽屉里没有账号、密码输入框。** 这是保护用户直觉的决定，理由见 §6.3。
- 「自动登录」开关：关掉即停止使用已存凭据（密文保留，直到用户清除）；打开时若尚无凭据，提示「下次登录时保存」。
- **「收起公告弹窗」开关：收掉教务系统那个关不掉的公告弹窗。** 站点首屏会弹一个全屏模态公告窗
  （`.el-dialog__wrapper.notice-dialog`，19 条公告），**它自己没有关闭按钮**
  （`el-dialog__header` 里关闭按钮的槽位是注释掉的 `<!---->`，也没有页脚），实测点遮罩、点弹窗外都不关。
  所以只能整层摘掉：弹窗容器 + 遮罩 `.v-modal` + 滚动锁 `el-popup-parent--hidden`，**三者必须一起处理**，
  只隐藏弹窗内容会得到「内容没了、遮罩还在」的空白页。开关关掉即原样还原。结构与判据见
  `docs/PROTOCOL.md` §9。公告并没有变得不可达——站点右侧自带「通知公告」悬浮入口。
- **「清除缓存 · 退出登录」：只清登录状态，不删密码。** 登录状态就是 cookie（实测凭证全在 cookie 里，
  见 `docs/PROTOCOL.md` §5），所以清掉 cookie + 缓存就等于退出登录；已保存的凭据与「自动登录」意愿
  都不动，下次打开还会自动填回来。删除 cookie 是异步的，必须等回调再重新加载，否则旧 cookie 会跟着
  那次请求出去，用户看到的是「点了退出却还是登录状态」。
- 「清除账号」：删密文并删掉系统密钥库里的密钥条目（旧密文从此不可解），登录状态不动。
- 「改用其他账号」：清会话**和**本机凭据 + 回到 P1（重新走一次同意流程）。
- 抽屉里显示的用户名**必须打码**（`2021****`）——打码是为了别人从旁边扫一眼看不到完整学号。

## 4. 路径时序

### 4.1 首次使用（未保存账号）

1. 打开 → **P1**。
2. 点「教务系统」→ P2，状态行「正在打开校园网关…」。
3. 未登录 → 门户页 → 读出教务系统入口前缀（存起来）→ 跳 SSO 支点 → 落到统一身份认证页。
4. 状态行换成**常驻**告知：「登录一次，之后自动登录」（若用户取消勾选则显示「本次登录不会保存账号」）。
5. 应用只做页面上的辅助：勾「记住我」；若正文含「密码已过期」，**先按文字找「点击跳过」并点它**
   （**不假设元素类型**——实测出现过 `<input type=button>`，而本文档早先记成 `<button>`，是错的）；
   找不到才**重载当前 URL**（那正是该按钮 `onclick` 所做的事）。一次运行最多跳一次，
   跳完又回到这一页就停手并提示用户。
6. 用户输入账号密码 → 按下「登 录」。
   - 若已同意保存：在**提交那一刻**读取两个输入框，暂存在内存（不落盘）。
   - 若出现滑块：自动拖动；失败则状态行转告警「验证没能自动完成，请手动拖动」。
7. 落到教务系统首页 → 状态行「已进入教务系统」，2 秒淡出。
   - 暂存的凭据**此时才**加密落盘；底部出现一次性提示：「已记住账号，下次自动登录　[撤销]」。
8. 若出现「密码错误」文案 → 丢弃暂存（本来也没落盘），状态行常驻告警「账号或密码不对，请手动
   登录」，并把服务端给的剩余次数一并说出。**不自动重试**。

### 4.2 冷启动（已保存账号）——主路径

1. 打开 → **直接进 P2**，状态行「正在打开教务系统…」。
2. 直接打教务系统 SSO 支点（用缓存前缀）。
3. 落到认证页 → 自动填写账号密码、勾「记住我」→ 提交 → 需要滑块则自动拖。
   - 状态行依次：「正在自动填写账号…」→「正在自动完成安全验证…」（后者是常驻的，直到判决或超时）。
4. 落到教务系统首页 → 「已进入教务系统」→ 2 秒淡出。**全程零操作。**
5. 若出现「密码错误」→ 说明存下来的凭据已经不对：**删除凭据 + 关闭「自动登录」**，停手并提示剩余
   次数（见 §6.6）。**不重试**——每重试一次，都是替用户消耗一次失败次数。
6. 若前缀已失效（编码变了）→ 自动清缓存、回门户重读一次；
   状态行「入口地址已失效，已清除记录；请点「教务系统」重新进入」。只重读一次，不循环。
   写盘失败时口径必须跟着变（见 §5 的「前缀没清掉」行）——**不能在没写成功时说「已清除记录」**。
7. 若落到换票中转页（`/wengine-vpn/failed`）→ 不判失败、**不清前缀**，等页面自己往下跳；
   停留超时也只重载一次。
8. 若落到任何**既非认证页、也非中转页**的门户页（`entry=WEBVPN` 那一支）→ **先验正文**
   （含 `个人信息` / `注销` / `资源站点` 才算到达，见 `CORE-SPEC.md` §2）；没命中就**不宣布到达**，
   状态行「正在等待门户加载完成…」，等页面继续跳。

### 4.3 打开 WebVPN

与主路径同一条链，只在第 1 步换成门户地址，落到门户即停手（不强行进教务系统）——
但**要先验正文**（见 §4.2 第 8 条）：URL 落在门户主机只说明「到过」，中转页与门户自己的错误页
都满足它。遇到认证页照样自动填写。

### 4.4 会话过期（用着用着掉线）

任何一次跳到认证页，都按 4.2 的第 3 步处理：**有凭据就自动重新登录**，用户不用做任何事。这正是保存凭据的最大收益。

| 换票中转 | 正在跳转… | 否 | — |
| 断网 | 网络不通，请检查后重试 | 是 | 「重试」 |

规则：文案里**不出现**技术名词（不写「SSO」「302」「Cookie」），不出现感叹号，不出现「失败」以外的负面词。

**「剩余次数」是追加而不是替换**：否定文案先说是哪一种否定（手动输错 / 已存凭据失效），
再把次数信息接在后面。早先实现里两者是三选一，于是「再错一次就锁定」对「用已存凭据被否定」
永远不可达——而那恰好是最可能只剩一次的场景（每次冷启动都会自动消耗一次）。

**「是否可点」那一列不是装饰**：三端都必须真的渲染出可点动作
（PC 是工具栏上的动作按钮、Android 是状态胶囊里的 `TextButton`、iOS 是状态胶囊里的 `Button`），
并且动作的语义与文案一致：「重试」＝重新加载当前页；「清除账号」/「撤销」＝清掉本机凭据并关掉自动登录。

## 6. 凭据生命周期与安全边界

### 6.1 生命周期

```
[同意]  P1 勾选「登录后记住账号」 → 落盘 auto_login=true
   │
[捕获]  仅在 CAS 页 + 用户按下登录（submit 事件）那一刻读两个输入框
   │        → 明文只进内存（CharArray），标记 pending，不落盘、不打印
   │
[定局]  落到教务系统首页 → AES-256-GCM 加密落盘 → 清内存 → 提示「已记住账号」
   │     又回认证页（密码错） → 丢弃 pending，不落盘
   │     90 秒无结论 / 进程结束 → 丢弃
   │
[使用]  冷启动解密 → 注入认证页 → 立即清内存
   │
[清除]  抽屉「清除账号」/ 提示「撤销」 → 删密文 + 删密钥库条目
```

### 6.2 加密与存储（Android）

- **密钥**：`AndroidKeyStore`，AES-256-GCM，别名 `campus-entry-cred-v1`，**不可导出**；`setUserAuthenticationRequired(false)`（全自动的前提）；硬件支持时自动落到 TEE/StrongBox。
- **密文**：普通 `SharedPreferences`，存 `iv` + 密文（Base64）。GCM 自带完整性标签，解密失败一律当"没保存过"处理，不崩溃、不猜测。
- **不使用 `EncryptedSharedPreferences`**：该库已弃用。一手证据——androidx 源码里 `MasterKey`、`MasterKeys`、`EncryptedSharedPreferences`、`EncryptedFile` 全部带 `@Deprecated`，javadoc 写明 "Use `javax.crypto.KeyGenerator` with AndroidKeyStore instance instead" / "Use `android.content.SharedPreferences` instead"。官方指引就是"直接用系统密钥库 + 普通存储"，正好零依赖。
- **备份**：`android:allowBackup="false"`，并把凭据文件排除出任何自动备份/转移。密文离机也解不开，但仍不该外流。
- **代码结构**：`CredentialStore` 只依赖一个极小的 `CryptoBackend` 接口——生产实现走 AndroidKeyStore，单元测试用 JVM 上的 AES 实现。这样**存储格式、完整性校验、失败处理都能在电脑上单测**，不必依赖真机。

### 6.3 为什么只在官方页面填写（而不是自绘输入框）

应用画一个「学号 / 密码」输入框，是这类工具最常见也最糟的做法：用户看到一个第三方应用索要统一身份认证密码，**没有任何办法验证它不是钓鱼**。所以本应用界面上不存在密码输入框。

- 凭据只在**学校官方的统一身份认证页面**上输入，应用只负责"替用户重复这件事"。
- 因此捕获时机被限制为"用户在官方页面上按下登录按钮的那一刻"——这个动作本身就是他对"这组凭据是对的"和"我要提交它"的双重确认。
- 在应用里定制输入框的方案被否决，理由见 §8。

### 6.4 硬规则（不可协商）

1. **仅当当前文档主机是 `webvpn.sues.edu.cn`，且页面同时存在 `#username`、`#password` 与提交按钮时**才填写。网关改写的第三方页面、教务系统自己的二次登录页，一律**不填**。
2. **只提交一次**。密码错、滑块失败、网络异常，都不自动重试、不猜测兜底路线。
3. 凭据永远不进入日志、不进入剪贴板、不进入 Intent、不进入界面状态保存（`onSaveInstanceState`）。
4. 应用不申请任何与身份相关的权限；不采集、不上报、无第三方 SDK、无网络请求（除了访问学校站点本身）。
5. 用户名展示一律打码。
6. **密码错误 → 删除已存凭据并关闭「自动登录」**（判据与前提见 §6.6）。这一条没有例外。
7. 解析到剩余尝试次数 **≤ 1** 时，硬性阻断一切重试路径，并把次数原样告诉用户。

### 6.5 诚实的安全边界（必须让用户看到）

- 加密保护的是**静态数据**：落盘文件、云备份、设备镜像、被别人拷走的文件。这些拿到的只有密文，没有系统密钥库里的密钥，解不开。
- 加密**不**保护运行中的进程：设备已被 root、或攻击者能在本应用进程内执行代码时，内存里的明文和"让系统替我解密"的能力都在他手里。这不是"再努力加密"能解决的问题，任何声称能的说法都是假的。
- 最后一步把密码交给 WebView 时，必须经过一个 Java `String`，而 `String` 在 JVM 里无法擦除——这是真实存在的残留窗口（几毫秒到一次 GC）。它无法根除，只能缩短：读取即用、用完立即放弃引用、不复制、不拼接。
- 用户随时可以一键清除，且清除是**立刻生效**的（连密钥一起删）。

### 6.6 密码错误的判定与处置（依据 `D:\webvpn` 的实测记载）

**判据——不看 URL 形态**（认证页提交前后地址逐字节相同）：认证页文档里 `#msg1`（或
`name="error_fm1"`、`.form-error` 容器）的文本含 `密码错误` / `密码不正确` / `用户名或密码` /
`账号或密码` / `用户不存在` / `账号不存在` / `用户名不存在`。`#msg2` / `error_fm2` 是短信表单的，
不混用。取文本要深度感知：`<br>` / `<hr>` 是 void 元素、**不改变嵌套深度**，文案可能含嵌套标签；
不要用非贪婪正则（嵌套 `<div>` 会提前截断，整容器取文本会混入同容器里的 `swiSpan*` 空节点）。
HTML 实体要解码（`账号&amp;密码错误` → `账号&密码错误`）。

**剩余次数**：不写死句式——找所有 `(\d+)\s*次`，其前约 12 个字符内出现
`再` / `还` / `剩余` / `剩` / `可再` / `尝试` / `输错` / `错误` 即为剩余次数。
实测文案「密码错误。再输错3次，账号将被锁定。」→ 剩余 3。

**处置（自动登录路径——这是最危险的失败模式）**：

1. 提交的回应是**另一份新文档**（登录提交是整页导航，服务端把错误文案渲染成一张新的登录页，
   实测见 `docs/PROTOCOL.md` §6）。所以「这次否定是不是冲着应用填的那组凭据来的」**不能用
   「文档序号相等」判断**——那永远差一，已存凭据被否定时会漏删。正确做法是**待判决标志**：
   应用真的按下登录那一刻置位；用户自己提交、登录成功（到达目的地）、或重开流程时清掉；
   否定发生时**读走一次**（读走即清，第二次否定——用户改过后还是错——不会再次归因给应用、
   不会重复删库）。三端一致的实现与用例：`EntryFlow.consumeAutoVerdict`（Android/PC 各有等价单测）。
   每次流程里替用户提交的次数还要有**硬上限**（2 次）：服务端若只回一张干净表单页而不置错误
   文案，没有上限就会一份文档接一份文档地填下去，每一次都在消耗失败次数。
2. 看到密码错误文案：
   - 归因给已存凭据 → **立刻删除凭据 + 关闭「自动登录」**。理由：这条文案只可能来自服务端对凭据的
     否定，不可能由网络或渲染问题造成。留着错的凭据，等于每次打开应用都自动替用户消耗一次失败
     次数，直达 5 次锁号。
   - 用户手动输入的 → **不动凭据**，只提示；并且要在否定页上**重新装上凭据监视器**——
     用户改对密码再登一次的那次提交，理应被捕获并保存（首次「登录一次，之后自动登录」的
     承诺才算兑现）。
3. 停止一切自动动作（不再填、不再提交、不再拖滑块），页面交给用户。
4. 文案：`保存的账号已失效，请手动登录` / `账号或密码不对，请手动登录`；解析到剩余次数时追加
   `还可以试 N 次`；剩余 **≤ 1** 时改说 `再错一次就锁定了，请先确认密码`。

**为什么必须有这一条**：不删凭据的实现，会在用户改过密码之后，把这个应用变成一台"每次启动自动
替用户输错一次密码"的机器。这是所有"保存密码自动登录"实现里最容易踩、后果最重的坑。

**密码已过期是不同的路径**：正文含 `密码已过期` 时**不消耗失败次数**（与密码错误有本质区别），
处理方式是**重新加载当前 URL**——页面上那个「点击跳过」按钮的 `onclick` 就是
`document.location.href = document.location.href`，重载后服务端凭 session 里已记录的
「凭据已校验 + 滑块已通过」直接签发 ticket，因此**不依赖任何按钮选择器**。
该提示**只对部分账号弹出**，不弹属正常路径，不得当成异常。

> 关于选择器：`D:\webvpn` 里记载的形态是
> `<button class="login_btn" onclick="document.location.href=document.location.href;">点击跳过</button>`
> ——类名确实是 `login_btn`，但元素是 `<button>`、文字在文本节点里。本工作区此前把它记成了
> `input.login_btn[value=点击跳过]`，在 `D:\webvpn` 的记载里找不到依据。真机上会验证一次；
> 新的做法按文本判定并重载，**不依赖这个差别**。

## 10. 已修的六处罚据／顺序错误

1. **换票中转页会被误判成「前缀失效」，从而删掉一个好前缀。**
   `MainActivity.route()` 里 `fromCachedPrefix && !casSeen` 这一条，本意是"前缀编码过期"，但
   `/wengine-vpn/failed` 恰好满足"用缓存前缀直打、落到不是教务系统、本次没经过认证页"。
   实测那条路径随后会正常落到首页，于是用户看到的是"入口地址已失效"的假警报，缓存还得重读一遍。
   修法：把中转页加进身份表（§2），让「前缀失效」这一条只对**真正不认识**的落点生效。

2. **「点击跳过」的判据不该假设元素类型。**（这一条我第一轮判断错了，下面是更正）
   原先按 `input.login_btn[value=点击跳过]` 找，而 `D:\webvpn` 的夹具里那个按钮是
   `<button class="login_btn" onclick="document.location.href=document.location.href;">点击跳过</button>`
   —— 于是我判定「按 `input` 找永远找不到」。但后来在共享浏览器实测登录页，按钮其实是
   `<input class="login_btn" value="登 录">`：**这个主题的按钮就是 `input`，旧选择器很可能本来是对的**。
   正确的修法不是二选一，而是**不假设元素类型**：按文字找（`input` 看 `value`，`button` / `a` 看文本），
   找不到再重载当前 URL（那正是该按钮 `onclick` 所做的事）。同时把「密码已过期」与「密码错误」
   分成两条不同的路径：前者不消耗失败次数、可自动跳过；后者立刻停手。

3. **滑块的滑轨长度算错，于是每次拖动都偏短。**（真机上三次拖动全部偏移后查出）
   `PageJs.dragJs` 第一版把**提交值域**（360）乘上显示缩放当成了**滑轨长度**——正确值是手柄能走的
   显示层像素 `330 − 45 = 285`。提交值因此变成 `0.947x`：一直偏短，x 越大偏得越多（x=200 差 11px、
   x=360 差 19px），远超服务端 ±2 容差，表现就是「每次都偏移」。
   更糟的是那份实现里 `zoom` 取自 `ctr.style.width ÷ 60`，页面若不写行内宽就直接算不出来。
   修法：把这段算术从注入的 JS 字面量里**搬进 `SliderDrag`**（纯逻辑、11 项单测，含全域
   `286/361` 精确命中与 ≤1px 最大误差的守恒断言，以及真机那三次偏移的原始数据），
   JS 只负责量几何与派发事件。**根因不是那条公式，是「算术写在电脑上测不到的地方」**。

4. **过期判据的优先级写反了，导致过期页既不跳过也不提示。**（真机反馈「为什么没有跳过」）
   第 2 处的修法里，我在注入的 JS 里按「先看有没有服务端提示文本、再看正文有没有 `密码已过期`」
   的顺序返回状态——而**过期提示的文案本身就写在 `#msg1` / `.form-error` 那个容器里**，于是通用
   提示把更具体的过期判据整个挡住了。表现：底栏显示「正在自动完成安全验证…」（说明走了「装滑块
   监视器」那条分支），页面上却明明白白写着「您的密码已过期」，停在那儿不动。
   修法：页面侧只**原样回报观察**（是否过期 / 有无表单 / 有无滑块 / 提示文本），优先级由
   `Sues.casKind` 决定，并由 `SuesTest.过期优先于提示文本` 钉住。
   顺带把「跳过」限制为**一次运行最多一次**：跳完又回到这一页，说明 session 里没有「凭据已校验」，
   反复重载只会把页面刷个不停，这时停手交回用户。

5. **密码错误的归因按「文档序号相等」判断，永远差一。**（2026-09-19 做 PC 端时审查发现，
   未及在真机上造成事故）登录提交是整页导航，服务端的否定渲染成**下一份新文档**；用
   「`usedSavedDoc == documentOrdinal`」归因必然不成立——已存凭据被否定时**不会删除**，
   应用就成了「每次启动自动输错一次」的机器。修法：待判决标志（见 §6.6 处置 1），
   三端各有等价单测（`EntryFlowTest` 的归因五例）。

6. **滑块监视器的首次上报会把状态行清空。**（2026-09-19 PC 端实测发现，Android 同样存在）
   `captcha-watch.js` 装上后第一次上报必然是 `armed=false`（页面有密码框、还没提交），
   宿主把这个状态变化当成「收起提示」处理，把「登录一次，之后自动登录」这类本该留下的提示
   在 400ms 内擦掉。修法：`armed=false` 只撤超时定时器、不动状态行——**滑块监视器不拥有
   状态行**，提示由后续的判决（成功/失败/到期）来替换。

前两条是**先有实测、后有代码**的典型：`D:\webvpn` 的记载早就写清楚了，是实现时按印象补的选择器和
分支。第 3、4 条的层次不一样：都是**把判断写进了电脑上测不到的地方**（JS 字面量），
所以修法统一是「页面侧只观察、判断回纯逻辑层、由测试钉住」。第 4 条还额外说明了一件事：
**规格里写对了公式/顺序，不等于实现里就对了**——第 2 条我更正之后引入的新顺序，
恰恰是因为没人能对一段 JS 字符串写测试才活了下来。
